Notes for implementation

The dual-axis problem

APEST(d) and PEP are scored from the same 36 cards, so they aren't independent in practice: someone who sorted everything into the middle buckets will be flat on both. Running two separate round-robins could mean 12–16 extra questions, which is longer than the assessment itself.

Shared budget

One budget covers both scales (default 10). Allocation rules:

  • Only one scale tied → it can use up to the full budget, including a second round of different statements for extra reliability.
  • Both tied → second rounds are dropped first, then pairs are trimmed from whichever scale has more, until the total fits.
  • Pairs are priority-ordered before trimming: comparisons involving the top-ranked categories survive, comparisons between 3rd and 4th get cut first. Resolving who is first matters more than ordering the tail.

Interleaving

Questions alternate between the two scales rather than running in blocks. Six consecutive questions about your role with people creates a consistency pull — people start answering to match what they've already said rather than what's true. Alternating breaks that. It also stops the second scale getting all the fatigued answers.

The cost is context-switching, which is why each question carries a quiet one-line label. Toggle interleaving off in the harness to compare.

Comparisons never cross scales

Every pair is within one scale. Comparing "I'd rather start something new" against "I finish what others start" would be meaningless — they're different axes, and someone can legitimately be high on both.

Integration contract

const plan = planTieBreak(
  { apest: apestScores, pep: pepScores },
  { threshold: 4, maxCluster: 4, budget: 10, interleave: true }
);

if (plan) {
  // plan.questions → flat ordered list, each tagged with its axis
  // plan.axes      → per-axis cluster info, for the intro copy
  // ...run UI, collect picks
  const out = resolveAll(plan, picks);
  // out.apest / out.pep → same shape in as out: [{id,label,pct}]
  // out.cycles         → array of axes where preferences were circular
}
